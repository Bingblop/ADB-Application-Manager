Make your own font for a Samsung phone from a font file (.ttf or .otf): a Regular, a Bold if you have one, and colour emoji inside if you like. The app turns it into a Samsung font package that you can install, and with Root, or with Shizuku running as the Android system user, it can put the font on the phone directly. The tab also finds and downloads fonts from Google Fonts, shows and downloads five emoji fonts, and with root it can use one as the phone's own emoji until the next restart.

Where to find it: the tab named Custom Fonts (two lines on the tab bar, Fonts on the bottom bar, with an "Aa" icon), after Root Features and right before About. It is on out of the box but not pinned to the bottom bar, so it waits under More. If it is missing, it was switched off: see Turning tabs on and off and moving them.

Before you start

  • Making a font needs nothing special: no working mode, no internet, any phone. The work is done on the phone. Only the Google Fonts page, the emoji font downloads and the iOS emoji sample need an internet connection.
  • Installing or applying it needs a Samsung phone. Samsung phones change their font through Samsung's font system, FlipFont (made by Monotype), and that is what these packages are for. On another make the tab still builds fonts and can export them, and My fonts says "Font packages work only on Samsung phones. You can still export them."
  • A font file you are allowed to use. A font is someone's work and has a licence. Many free fonts allow changing them (the SIL Open Font License, for one). A font whose maker forbids it carries a mark, and the app then warns: "This font's maker does not allow it to be embedded or changed ("restricted license" in the font). Use it only if its license lets you."
  • The Font changer (putting the font on the phone directly) needs the Root working mode with su granted, or Shizuku running as the Android system user (UID 1000) or as root (UID 0). The system user is Android's own system account: more privileged than the shell user, but not root. Shizuku as the shell user (UID 2000), Wireless Debugging and ADB over TCP cannot do it: Android does not let the shell user write the phone's font folder.
  • System emoji needs Root with su granted, or Shizuku running as root (UID 0). The system user is not enough for it.
  • Emoji in the COLRv1 format (Noto Color Emoji, Blobmoji) show inside a font on Android 13 and newer only. Twemoji works from Android 8, and so does OpenMoji, because on Android 8 to 12 the app downloads its COLRv0 build instead.

The Make a font card turns a font file, a second one for Bold if you like, and an emoji font if you like, into a Samsung font package. It all happens on the phone, and it needs no working mode.

Before you start

  • Put the font file on the phone: a .ttf or .otf file, for example in Downloads. Or take a family from Google Fonts: the link Find one on Google Fonts under the Regular row opens the Google Fonts page, whose Use in Make a font fills the card for you (Finding a font on Google Fonts). A font collection (.ttc, several fonts in one file) and a web font (.woff, .woff2) are refused.
  • For Regular, choose the upright (not italic) file of the family. The Regular is what the phone draws all ordinary text with, so an italic one would slant everything.
  • If the family has a separate Bold file, have it ready too. A variable font has its Bold inside: see Variable fonts.

Step by step

  1. On the Regular row ("A .ttf or .otf file"), tap Choose. Android's file chooser opens; pick your font. While it is open, the Choose and Change buttons of the card are greyed out, so one chooser cannot be opened on top of another; they come back when you pick a file or come back without one. Build font waits as well until the file you picked has been read, so a build never takes the file chosen before it. The row then shows the file name and a line such as "Lato Regular · 2,164 glyphs · TrueType outlines" (a glyph is one drawn shape of the font), with "Variable font" at the end when it is one, and the button reads Change. Anything worth knowing about the file is listed under the row.
  2. A preview box appears: "Aa Bb 123" and "The quick brown fox jumps over the lazy dog." in your font, and the same sentence in bold, drawn the way the phone will draw bold text with your choice of Bold. The Name box fills in with the font's family name. A variable font also gets a panel with Style and sliders (Variable fonts).
  3. Choose the Bold: None, Same variable font, another weight (offered for a variable Regular, and chosen by itself when the font reaches a heavier weight than your Regular), or Another font file, which adds a Bold font file row with its own Choose. A variable font that cannot go heavier (it has no Weight axis at all, or none above the Regular's weight) leaves Bold at None, so Android makes bold text from the Regular instead of building a second, identical font. What None means is below.
  4. Choose the Emoji: None keeps the phone's own emoji; the emoji fonts you downloaded on the Emoji fonts card are listed by name; My own emoji font file adds an Emoji font file row ("A COLR emoji font"). With nothing downloaded the card says "To add emoji, download an emoji font under Emoji fonts, or choose your own file." See Emoji fonts.
  5. Check the Name ("The name in Samsung's font list", up to 40 characters). It is the name in Samsung's Font style list, in My fonts, and in Android's list of apps once the package is installed. It needs one character you can actually see: a name of only spaces, or only invisible filler characters such as the Hangul filler U+3164 or the blank Braille pattern U+2800, gets the hint "The name needs at least one letter, digit or sign that can be seen." under the box and leaves Build font off.
  6. Tap Build font. It stays greyed out until a Regular is chosen and the Name shows at least one character (and the Bold or emoji file, when you chose to use one). It also stays off while something would have to be settled first: your Regular or Bold already has colour glyphs of its own and Emoji is not None, or your own emoji file is COLRv1 and this phone's Android is older than 13, which cannot show it inside a font ("Needs Android 13 to show inside a font."). A bar shows each step: "Reading the font files...", "Fixing the variable font at the chosen weight...", "Converting the outlines to TrueType...", "Putting the emoji in...", "Making the font package...", "Signing the package..." and "Saving...". A big font with emoji inside can take a little while.
  7. When it is done the card says "Lato is ready in My fonts." (with your Name), followed by any warnings, and the font is listed in My fonts. Cancel during the build stops it and says "The build was cancelled."; nothing is kept.

What Bold "None" means

Apps draw headings, buttons, names in a chat list and other bold text with the Bold font. With None, the package holds only your Regular font ("Without a Bold font, Android makes bold text from the Regular one."): when an app asks for bold, Android thickens the Regular letters by itself. That works, but a Bold drawn by the font's designer usually looks better, so choose one when the family has it. The third line of the preview shows bold made from the Regular, roughly as the phone will. If the Bold you choose is no heavier than the Regular, the app warns: "The Bold font is no heavier than the Regular one, so bold text will look like the rest of the text."

What the app does to your font

  • A variable font becomes a fixed font at the point you chose (Variable fonts).
  • PostScript outlines (CFF, which many .otf files use) are converted to TrueType outlines, the kind the package's .ttf files hold. The curves move by a small fraction of the letter's size, too little to see.
  • Emoji are put inside, when you chose some (Emoji fonts).
  • The names inside the font become your Name, with the styles Regular and Bold (an italic file stays italic).
  • A last check: the finished font is read again and every glyph is decoded before it is kept, so a damaged result is refused rather than packaged. Your original file is not changed.

What the package is

An ordinary Android package with no program code in it: the font files and a small file that names them for Samsung's font system. Its package name is com.monotype.android.font. followed by the letters and digits of your Name, an underscore and six letters and digits, for example com.monotype.android.font.Lato_8b21d0; My fonts shows it under the name. It is signed with the key this app makes on your phone for signing APKs, which never leaves the phone (Privacy).

A variable font holds a whole range of styles in one file: every weight from thin to black, and sometimes widths, slants or sizes. Samsung's font system needs fixed fonts, so the app makes a fixed copy at the point you choose: one for Regular and, if you like, one more for Bold, both from the same file.

The words

  • Axis: one way the font can change. The usual ones are named on the screen Weight, Width, Optical size, Slant and Italic; a font's own axes show the name the font gives them.
  • Named style (an instance): a point on the axes the designer gave a name, such as Light, Regular, SemiBold or Bold.
  • Weight 400 and 700 are the usual Regular and Bold.

Step by step

  1. Choose a variable font as the Regular. Its row ends with "Variable font", and a panel opens under it: a Style drop-down with the font's named styles, and one slider per axis, its value shown on the right.
  2. The app starts the Regular at weight 400, or as near as the font goes, using the font's own named style when one is there. Pick another named style under Style, or move a slider. Away from every named style, Style reads Custom; it goes back to the name when you land on one.
  3. The preview follows at once, so you can see the weight before you build.
  4. Bold switches by itself to Same variable font, another weight when the font reaches a heavier weight than your Regular (and unless you had changed Bold already), with a panel of its own that starts at weight 700, or as near as the font goes. Change it the same way. The bold line of the preview shows it.
  5. A variable font with no Weight axis (some display fonts vary only in width, slant or shape) leaves Bold at None: a second font at the same point would be the same font, so Android's thickened Regular is the better bold. Choose Same variable font, another weight yourself and a note says "This font has no Weight axis, so this Bold would look like the Regular. With None, Android makes bold text from the Regular."; drag the Bold's Weight slider to or below the Regular's and the note reads "This Bold is no heavier than the Regular, so bold text would look like the rest of the text." Both are notes, not refusals: Build font stays on.
  6. Tap Build font. The step "Fixing the variable font at the chosen weight..." makes the fixed fonts, and the rest goes as in Making a font.

A variable file chosen under Another font file for Bold gets its own panel too. And you can set Bold to None for a variable font: then only the Regular point is kept, and Android thickens it for bold text.

What the fixed font keeps and leaves out

  • It keeps the letters as they are at the point you chose, their spacing, and the font's kerning and ligatures at that point.
  • It leaves out every other point, so the phone cannot change its weight later; the file is smaller for it. Axes the font marks as hidden are not shown and stay at the font's default.
  • Two warnings can appear: "A few kerning or mark positions of this font could not take their variation at this location." and "This font's colour glyphs change with its axes; the static font keeps them as they are at the default location." Neither stops the build.
Tip. A real Bold from the same variable font nearly always looks better than the thickened Regular Android makes without one. Keep the two at least about 200 apart on the Weight axis, so bold text stands out.

Google Fonts has about two thousand font families that are free to use. Search Google Fonts opens a page over the tab where you can browse them, see each one drawn in its own letters, download a family to the phone and hand it to Make a font. The rest of the tab stays as it is underneath.

Where to find it

  • The Search Google Fonts button on the top card of the tab (Custom Fonts). Once the list is on the phone, the button also shows how many families it has, such as "1,950 families".
  • On the Make a font card, while no Regular file is chosen, the link Find one on Google Fonts under the Regular row.

The page slides up over the tab. Close (the X) closes it. On a family's page, the arrow left of its name goes back to the list. Android's Back button, or a tap above the page, goes back one step: from a family's page to the list, and from the list to the tab. The top of the page, where its title is, works like the grab line of other sheets: pull it up and the page takes the whole screen, pull it down and it goes back to its size. One more pull down goes back one step, as Back does: from a family's page to the list (not out of the page), and from the list to the tab.

Before you start

  • An internet connection. The list, the previews and the downloads come from Google Fonts. Fonts you already downloaded stay on the phone and work without one.
  • No working mode, and no Google account. The app reads the same public addresses the Google Fonts website uses. It needs no key and sends nothing about your phone. What you type to preview goes to Google Fonts with the previews (Privacy).

The list

  1. The first time, the page says "Getting the list of fonts from Google Fonts…" and then shows it. The app keeps the list on the phone. When the list is over a week old, the app uses it and gets a new one in the background. The line "List updated Oct 1, 2026 · Refresh" (with the date of your list) says how old it is. Refresh gets a new one now.
  2. Type in Search fonts or designers. Letter case and accents do not count, and every word you type must match the family's name or one of its designers.
  3. Narrow the list with All categories (Sans serif, Serif, Display, Handwriting, Monospace) and All languages (the scripts and languages a family covers). Sort it by Popular, Trending, Newest or Name (A–Z). The Variable and Downloaded chips show only variable families, or only the ones on this phone. The line above the list counts what is shown: "1,950 families" (with the number of your list) when nothing narrows it, or "12 of 1,950" when a search, a menu or a chip does.
  4. Each card shows the family's name, its category, its designer and how many styles it has. It can have the tags VARIABLE, COLOUR (the family draws in colour), DOWNLOADED and NO LONGER ON GOOGLE FONTS (see "A family that left Google Fonts" below). Under that, a line of text is drawn in the family's own font. The list shows 30 cards at a time, and Show 30 more at the bottom (with how many are left) adds more.
  5. To see your own words in every font, type them in Type something to preview. The Size slider sets how large the previews are. Families for another script, such as Arabic or Japanese, show a sample in their own script until you type, and the emoji families show emoji. The letters you type go to Google Fonts with each preview, so that it can send them in each family's font; what you type in Search fonts or designers is not sent, but the families it finds ask for their previews by name, like any card on the screen.

The previews come only for the cards on the screen, and a few below them. Each is a small piece of the font, with just the letters it needs. While a preview is on its way, its line stays blank, so you never see the text in the wrong font. If Google Fonts sends none, or the preview draws none of the letters (your words in an emoji family, for example), the card shows the family's name in the app's own font with "No preview" after it, and the card still works. So does a family with no Latin letters and no sample of its own script. Previews are kept for a while (up to 24 MB), so the list scrolls quickly the next time.

A family's page

Tap a card. The family's page opens with its name at the top, drawn in its own font, and a line with its category, designers, the number of styles and, for a variable family, its axes (for example "Variable: Width, Weight").

  • Font files comes first: Download, and once the family is on the phone, what to do with it (below).
  • Type tester: your own text, its Size (14 to 96), and one slider per axis for a variable family (Weight, Width and the family's own axes). The large line below follows the sliders as you move them.
  • Styles: one line per style the family has, such as "Thin 100", "Regular 400" or "Bold 700 Italic", each drawn in that style. A family with more than 18 styles shows "No preview" on the lines past the eighteenth.
  • About this family: what Google Fonts says about the family, its Licence (with Licence text to read it in full), its designers, when it was added and last updated, and Open on fonts.google.com, which opens the family's page in your browser.

A line of the page whose preview does not come, or draws none of its letters, shows its text (the family's name at the top, your text below) in the app's own font with "No preview" after it.

A family that draws in colour, or a symbol family, gets a note: "This family has colour glyphs. Make a font needs a plain text font, so this one may not work there." or "This is a symbol family. Make a font needs a plain text font, so this one may not work there."

Downloading a family

  1. On the family's page, tap Download. Under it, "2 font files" says how many files will come. For a variable family the app takes only its variable files (usually one upright and one italic), because they hold every weight. For any other family it takes every style.
  2. A bar shows the progress of the whole family, and the line under it the file on its way ("File 1 of 2 · 120 KB of 205 KB": the sizes are those of that file as it comes over the network, packed smaller by Google Fonts, so they are usually smaller than the file takes on the phone; they start again with the next file). Cancel stops it and keeps nothing. You can go back to the list or close the page while it downloads. When it is done, a message says "Roboto downloaded" (with the family's name). If it fails while you are elsewhere, a message says "Roboto was not downloaded." and why, and the family's page says why again when you open it.
  3. The app checks every file before it keeps the family. It must come from Google's font server (fonts.gstatic.com), have a plain font file name (.ttf or .otf), be at most 64 MB (160 MB for the whole family), and really be a font. The family's licence file is kept with it. The app notes each file's SHA-256 checksum and checks it again when it uses or saves the file, so a file that changed on the phone is noticed.

The page then says "Downloaded · 2 files · 790 KB" (the space the family takes on the phone) and offers:

  • Use in Make a font: closes the page and puts the family into the Make a font card, as if you had chosen the files yourself. A variable family goes in as the Regular, and Make a font then offers its own Bold at another weight (Variable fonts). For any other family, choose the files first under Regular and Bold on the page. The app picks the 400 upright file and the 700 upright one for you when the family has them, and Bold can be None. While a font is being made, a file chooser is open, or the files you chose are still being read, the button waits, and the page says why.
  • Save to phone: saves the family as a .zip (its font files and its licence) wherever you choose, for use in other apps. If the save fails after you left the family's page, a message says "Lato was not saved." (with the family's name) and why, and the family's page says why again when you open it.
  • Delete: removes the family from the app at once, without asking, because downloading it again takes a moment. Fonts you already made from it keep their own copy. A family marked No longer on Google Fonts cannot be downloaded again, so for it Delete asks first ("Delete Lato?", with the family's name): tap Save to phone before, if you want to keep a copy.

A family that left Google Fonts

Google Fonts sometimes renames or removes a family. If it does that to a family you downloaded, the next list (after Refresh, or the weekly update) no longer has it, but its card stays, with the tags DOWNLOADED and NO LONGER ON GOOGLE FONTS, and it still counts in the number of families. Its page says "This family is no longer on Google Fonts. Its downloaded files still work here." Use in Make a font, Save to phone and Delete work as for any downloaded family, but it cannot be downloaded again. Google Fonts no longer has its previews or details, so its lines show "No preview", and About this family shows only the name of its licence: no description, no Licence text and no Open on fonts.google.com. Once you delete it, its card leaves the list. If a new list comes while the page of a family it dropped is open, a downloaded family's page stays and changes at once; any other goes back to the list.

The licence, and the Reserved Font Name

Most Google Fonts families are under the SIL Open Font License (OFL). A few are under the Apache License or the Ubuntu Font Licence. All of them let you use the font and make changed copies of it. A font made on this tab is a changed copy (fixed at one weight, renamed, sometimes with emoji inside). Some OFL fonts keep their name for the original only, which the licence calls a Reserved Font Name. When the family has one, its page says, for example, ""Lato" is a Reserved Font Name: a font made from this family must have another name.". After Use in Make a font, the Name box is left empty instead of being filled with that name. If you type a name that holds it, the box warns: "Lato's licence keeps the name "Lato" for the original font. A font made from it is a changed copy, so give it another name." The warning follows the files: a Regular you then choose from a file of your own takes the family's names away, but a Bold from the family keeps them while Bold is Another font file.

The Ubuntu Font Licence (the Ubuntu families, such as Ubuntu, Ubuntu Mono and Ubuntu Sans) keeps the family's own name for the original in the same way, though it has no Reserved Font Name line. The family's page says, for example, "Ubuntu is under the Ubuntu Font Licence: a font made from this family must have another name, or "Ubuntu derivative" and a name of your own." The licence also allows a name such as "Ubuntu derivative Mine" (the family's whole name, the word "derivative", then a name of your own: for Ubuntu Mono, "Ubuntu Mono derivative Mine"), and that name gets no warning. That way out is the Ubuntu Font Licence's only: under the OFL, "Lato derivative Mine" still holds the Reserved Font Name and is warned about.

Downloading

  1. Tap Download. A bar shows how much has arrived ("2.1 MB of 4.8 MB"); Cancel stops it and keeps nothing, also while the app is still reaching the server.
  2. The app takes the file from the one address written into the app for it, and checks two things before it keeps it: the exact size and the SHA-256 checksum, both also written into the app. The Twemoji zip is checked, then its font is unpacked and checked again.
  3. If both match, a message says "Noto Color Emoji downloaded" (with the font's name), the row says Downloaded, and the font is offered under Emoji in Make a font (when this Android can show it inside a font) and on the System emoji card.

A download that does not match is deleted, never used: "The downloaded file is not the expected one (its checksum differs), so it was not kept." or "The downloaded file has the wrong size, so it was not kept." Other messages: "The download failed (...). Check the connection and try again." (the reason is in the brackets) when the server could not be reached; "There is not enough free space on this phone."; "The file is no longer at its address (HTTP 404). Update the app." when the server says the file is gone (HTTP 404 or 410), which trying again does not mend; and "The server answered HTTP 503. Try again later." (with the server's number) for any other answer. A download that Android cut short by closing the app leaves nothing behind: the app removes the unfinished file the next time the tab is used. Delete removes the file from the app; the fonts you already made keep their own copy of the emoji. It is refused with "Undo the system emoji first." while that font is the phone's emoji.

Why only some emoji fonts can go inside a font

  • COLR emoji are drawn from outlines and colours, the same way letters are drawn, so they can sit inside a text font. COLRv0 uses flat colours and shows on every Android this app runs on. COLRv1 adds gradients and shows only on Android 13 and newer; on an older phone those emoji would not appear, so the app does not offer them there, and does not make a font with a COLRv1 file chosen under My own emoji font file (OpenMoji comes in both, and an older phone gets the COLRv0 one).
  • CBDT and sbix emoji are pictures (bitmaps), and pictures cannot be combined with the outlines of a text font. Apple's emoji exist only as pictures, which is why the iOS row is for System emoji only. If you choose such a file under My own emoji font file, the card says "This font's emoji are made of pictures (CBDT or sbix), which cannot go inside a font. Choose a COLR emoji font."; a font with no colour emoji at all gets "This font has no color emoji (COLR). Choose a COLR emoji font." An emoji font file whose colour palette is missing or damaged, whose characters are not at their Unicode places, that is damaged or too complex for the app, or whose emoji would be too large for your font is refused when the font is made, with "Emoji font:" in front and "Choose another emoji font." in the sentence (Making a font).

How the emoji go inside your font

  • The whole emoji font is added to each face of your font, the Regular and the Bold, so each grows by about the emoji font's size: Noto Color Emoji adds about 5 MB to each.
  • Your font keeps its own letters, digits, space, punctuation, # and *, and the (c) and (R) signs, even where the emoji font has a picture for them. The emoji font gives every character that is shown as an emoji by default (Unicode's list), the skin tones, the flags, the combined emoji such as families, and the emoji form of digits, #, *, (c) and (R) when an app asks for it.
  • Android takes each character from the first font that has it. Keyboards send many emoji, the red heart among them, as a character followed by an invisible emoji selector; Android takes such a pair from the first font that lists the pair, and your font lists it for the emoji inside it. So in apps that draw text with the phone's font, these emoji are used instead of the phone's own. An app that draws emoji with its own pictures keeps them.
  • One font can hold at most 65,535 glyphs. Your font's and the emoji font's together must fit, or the build stops with "The font and the emoji together have more glyphs than one font can hold (65,535)."
  • The emoji are sized to sit with your letters as they sat with the emoji font's own.

The licences, if you share a font

On your own phone you may use all five. If you Export a font with emoji inside and give it to someone, the emoji go with it under their licence: OFL-1.1 (Noto Color Emoji, Blobmoji) and CC-BY-SA-4.0 (OpenMoji) ask that what you share stays under the same licence and names its authors; CC-BY-4.0 (Twemoji's pictures) asks that you name the authors. Your text font's own licence applies as well. Each row's License link has the full text.

Careful. The iOS emoji are Apple's art in a build made by someone else, and Apple does not license them for sharing. The Font changer puts one of My fonts on the phone by writing it straight into Samsung's font folder. It is the way to use your font on One UI 8.5, and it works on older One UI as well. Reset to Default puts the phone's own font back.

Before you start

  • A Samsung phone. On another make the card's tag reads SAMSUNG ONLY and it says "The font changer needs a Samsung phone."
  • Root with su granted, or Shizuku running as the system user (UID 1000) or as root (UID 0). The tag then reads ROOT, or SYSTEM USER for the system user. The system user is Android's own system account; it may write this folder, but it is not root. In any other mode the tag reads LOCKED and the card shows one row, "Apply a font", "Put one of My fonts on the phone, or go back to Default", with a Locked button and "Needs Root or the system user". See Root and Shizuku.
  • The tag always names the working mode as it is now, not the one a check was made in. Change the mode (Root to Shizuku as the system user, say) while a check is still running and the tag follows at once; the answer that comes back from the old mode is dropped, and the check is made again in the new one, so what the card says belongs to the mode you are in.
  • Know the way back before you apply anything: Reset to Default on this card, or Default in Samsung's Font style (Undoing what it changed).

Step by step

  1. Open Custom Fonts. The Font changer card shows Phone font: "Checking..." for a moment, then Default (the phone's own font) or the name of the font in use. If the check cannot be made (the mode dropped, the phone did not answer), Phone font reads Unknown, the reason stands under it in red, and a Try again button appears beside Reset to Default. Reset to Default stays usable while the font is unknown: it is the way back from a font that went wrong, and it should not wait on a check.
  2. In My fonts, look at the font's preview line, then tap Apply on its row. The button reads "Applying...".
  3. When it is done a message says "The font is applied.", the row reads In use, and Phone font names it. A box headed "Read back from the phone:" lists what the app read back afterwards: the contents of sans.loc, then each font file with its size, the start of its SHA-256 checksum and its label.
  4. Apps show the new font at once. If the message says "Done. Apps show the change once they restart." instead, the files are in place but the phone was not told to load them again: close and reopen your apps, or restart the phone.

Exactly what Apply writes

  1. The font files: /data/app_fonts/<user>/<folder>/DroidSans.ttf and, for a font with a Bold, DroidSans-Bold.ttf in the same folder. For a font without one, a DroidSans-Bold.ttf that an earlier version of the same font left there is removed (only that file), so bold text is made from your Regular. <user> is your Android user number (0 for the phone's owner); <folder> is the end of the font's package name, for example Lato_8b21d0. Each file is written as a .part first and checked for its exact size and SHA-256; one that matches waits beside the font in use as a .new file, and one that does not is deleted. Only when every file of the font has arrived whole does one last step check them again and move them into place together (and take the old Bold away). If any step fails, the app deletes what it had sent and stops with your current font untouched.
  2. The pointer: /data/app_fonts/<user>/sans.loc, the file Samsung's font system reads to know which font to draw. It holds the folder, a # and the folder's name, for example /data/app_fonts/0/Lato_8b21d0#Lato_8b21d0. It is written to a temporary file and then renamed, so it is never half written.
  3. Owner and label: the files belong to the system user (system:system) and everyone may read them, as Samsung's own font files; they get the SELinux label app_fonts_data_file (SELinux is Android's lock on which part of the system may touch which file).
  4. Samsung's Font style setting: two of Android's global settings, flip_font_style and font_style_index, are set to another value for a moment and then to your font, which makes apps load the fonts again.
  5. The read-back: the app then reads sans.loc, the files, their labels and their SHA-256 back, and that is what the box shows. Whether Apply worked is decided from this read-back, not from what the command said.

Nothing else changes: the system partition is not touched, and other fonts' folders are left alone. Reset to Default writes default#default into sans.loc, with the same owner, label, refresh and read-back, and says "The default font is back."; your copied font files stay in their folder, unused. Deleting the font in My fonts while Root or the system user is on removes that folder as well, and only that one; it is left while the phone's sans.loc still points at it. With the system user, Shizuku cannot read this app's private files, so the app hands each font file to it; the checks are the same.

Risky. The Font changer changes the font the whole phone draws text with: every app, Samsung's Settings, the lock screen and this app. A letter your font does not have is drawn in the phone's own font, but a font that draws badly, or very large or very small, can make text hard to read everywhere, including on the screens you need to undo it. A restart does not undo it. Before you tap Apply: look at the font's line in My fonts, and remember the two ways back, Custom Fonts, Font changer, Reset to Default, or Samsung's Settings, Display, Font size and style, Font style, Default.
  • The app checks the font when it builds it and checks each file after it is copied. It cannot see how the font looks on your phone.
  • When Apply or Reset fails, the card says what the phone did, in red, and keeps the read-back box, which is what tells you how far it got: "The phone did not take the font (sans.loc reads "...")." or "The phone did not go back to Default (sans.loc reads "...")." name what the pointer holds now. That message stays while the card checks the phone's font again, and the check's own trouble is a line of its own: neither hides the other. Leave the tab and come back, or change the working mode, and the message and the box go together: the card then asks the phone afresh. The System emoji card does the same with its own box.
  • Choosing a font in Samsung's Font style later replaces what Apply wrote. That is also a way back.
  • This has not been tried on a phone yet (Custom Fonts).

What it does

  • It copies the emoji font to /data/adb/adbmgr_fonts/, a folder of this app's own in root's part of the phone, and checks the copy's size and SHA-256. That is the only file it writes.
  • It finds the phone's emoji font files: every font Android lists as its emoji font (the und-Zsye families of /system/etc/fonts.xml and, on Android 15 and newer, /system/etc/font_fallback.xml), in /system/fonts or /product/fonts.
  • It never covers an emoji font Google Play services updated under /data/fonts/files. Android checks those files' signature (fs-verity): an app that loaded a covered one would close at once, and Android starting again would delete every updated font. A copy over the original in /system/fonts would not show on such a phone either, which is why the swap is refused there.
  • It notes which files it is about to cover, then lays the copy over each of them with a bind mount: the phone then reads the copy wherever it reads the original, while the original files stay exactly as they were. A bind mount lives in memory only, so a restart removes it. A file that already carries a copy of this app's is left as it is, so two swaps never pile up.
  • It reads back the checksum of each file before and after, and the box shows the one after.

Soft reboot

Soft reboot asks first: "Soft reboot?", "Only Android restarts, not the phone: the screen goes black for a few seconds and every app closes, without the boot screen. Unsaved work in open apps is lost. Faster than a full reboot; it does not clear everything a full one does." The question then says what the apps will come back with, and that depends on the card: with a swap on, "Apps start again with the new emoji. A normal restart puts the phone's own emoji back."; with none on (after an Undo), "Apps start again with the phone's own emoji."; and while the phone's emoji are Unknown, nothing is added rather than a guess. The red Soft reboot goes ahead. Every app closes, this one too: open it again afterwards and check the working-mode badge. A soft reboot keeps the swap. That is safe: Android checks its updated fonts again when it starts, and the swap never covers one of them.

Undo

  • Undo (shown while a swap is in use, and greyed out while the app cannot read the list of mounts) takes off only the copies this app laid; another tool's emoji on the same file, such as a root module's, stay. It checks that each file reads as it did before the swap, deletes the copy in /data/adb/adbmgr_fonts/ and reads back that it is gone, then says "The phone's own emoji are back." If a file did not come back, it says so: restart the phone to undo the swap. Apps that are open keep the swapped emoji until they start again.
  • Undo finds a swap from the phone's list of mounts, so it is offered even when the app lost its note of the swap (its storage was cleared, or it was closed in the middle of an Apply).
  • A normal restart of the phone always undoes it, so an emoji font that does not suit the phone cannot trap it. The copy is then unused. It stays in /data/adb/adbmgr_fonts/ until the next Use as the phone's emoji, which deletes it first, or until you delete that emoji font in Emoji fonts with root on. Undo is not offered after a restart: no swap is left to take off.
  • Deleting a downloaded emoji font in Emoji fonts with root on deletes its copy too. A copy that is still laid over a file is never deleted.
Careful. The swap reaches every app at once. An emoji the chosen font does not have shows as an empty box or not at all, and an app may draw emoji at a different size. If something looks wrong, tap Undo or restart the phone. Soft reboot closes every app without asking them: save your work first.
