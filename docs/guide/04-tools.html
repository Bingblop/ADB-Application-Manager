This tab lists the apps on your phone that a community project has studied, tells you in plain words how risky each one is to remove, and lets you uninstall, disable or restore them after a review step, with a history you can undo.

Where to find it: the third tab in the usual order, named UAD-NG Debloater. If it is missing, it has been switched off: turn it on again in the Feature List.

What debloating is

Bloatware means apps that came with the phone but that you did not choose: extras from the phone maker, your mobile network or Google. Some are useful. Others you never open, yet they take space or run in the background. Debloating means removing or switching off the ones you do not want (see the glossary).

The danger is that some preinstalled apps are parts of Android itself. Removing the wrong one can break calls, the keyboard, or even the start-up of the phone. So this tab tells you, for each app, how safe it is to remove. Read Debloating safely, step by step before you remove anything.

What UAD-NG is

UAD-NG stands for Universal Android Debloater Next Generation, a free community project. It keeps a long list of Android package names (a package name is an app's unique ID, such as com.example.app). For each package the list gives a short description, a removal level from safe to dangerous, the list it belongs to (phone maker, Google, mobile network and so on), and which other packages need it.

This app does not contain the list. It downloads it from the project's GitHub page, keeps a copy on your phone, and compares it with your apps. The levels and descriptions are the project's advice, not a promise that nothing will break on your phone.

Before you start

  • Looking at the list needs no working mode. Uninstall, Disable, Restore and Undo need one: ADB over TCP, Wireless Debugging, Shizuku or Root (see Working modes). In Read-Only mode, tapping one opens a sheet called Working Mode Required with a Set Up Working Mode button.
  • The list is downloaded the first time you open the tab (about 1.6 MB), so the first visit needs the internet. After that the tab works offline from the saved copy, and the app refreshes it when it is over a week old.
  • Make a backup first. Steps are in Debloating safely and Backups.

Step by step: removing or switching off apps

  1. Check that the status line shows a list and that a working mode is active (the badge in the header). Leave Recommended on.
  2. Read the description of each app you are thinking about, then tick a few. Select shown ticks every row that passes your filters, so use it only when you have read them all.
  3. Tap Uninstall, Disable or Restore. A sheet called Review: Uninstall Packages (or Disable, or Restore) opens. It lists every app that the action will touch, with its level. Nothing has happened yet.
  4. If the selection holds Expert or Unsafe apps, a red line warns that they can break important features and, for Unsafe, can make the phone boot-loop (restart again and again without ever finishing starting). Press Cancel if in doubt.
  5. Press the main button at the bottom of the sheet, for example Uninstall 3. A message says "Running on 3 packages...". When it ends, a Debloater Results sheet shows each app as Success or Failed with the phone's own reply. Press Done.
  6. Restart the phone and use it normally before you remove more.

Removing the wrong app can make the phone behave oddly or even refuse to start. This page is the careful way to do it: back up, start with the safest group, change a few apps at a time, test, and know how to put things back.

Needs: a working mode (ADB over TCP, Wireless Debugging, Shizuku or Root, see Working modes), a battery charged above half, and about an hour without hurry. Know your screen lock and your Google account password: after a factory reset you will need them.

Risky. A mistake can leave the phone stuck on its logo (a boot loop). Work in small steps, back up first, and never remove an app you cannot explain. If you cannot tell what an app is for, leave it alone.

What the four levels mean

The levels come from the UAD-NG project. The text is the one the tab shows under Removal Levels. Tap a row of the list to open it (its description, and what it is needed by or depends on); an opened row has its own Removal Levels button, which opens the same four levels in a sheet.

LevelIn plain wordsWhat can go wrong
RecommendedSafe to remove for most people, including apps you can reinstall from an app store. Still worth a quick review, since everyone uses their phone differently.You lose an app you did use, such as a preinstalled game, video or social app.
AdvancedBreaks minor or obscure features, overlays, or default apps (keyboard, gallery, launcher) that a better alternative can replace.Typing, photo viewing or the home screen stops working until you install another app for the job. A small setting stops working.
ExpertBreaks widespread or important features, but not basic operation. It should not boot-loop the phone unless the description says so, with no guarantee.Features you rely on can stop: for example calling extras, backup, or the camera's extra modes. This is hard to track down later.

Step by step

  1. Back up your own things. Copy photos, contacts and messages to your cloud account or a computer, the way you normally do. Removing an app deletes that app's own data, and a factory reset (the last resort below) deletes everything on the phone.
  2. Back up the apps you plan to touch. In the Application Manager, the Backups box saves an app's APK (its installer file), its permissions and its app ops in any working mode; the app's data needs Root (see Backups).
  3. Open the UAD-NG Debloater tab and let the list update. Check that the header badge shows a working mode.
  4. Keep only Recommended on. Leave State on On device. Tap your phone's brand chip to shorten the list. You will see rows with the app name, the package name and a description.
  5. Read every description. Tap a row to read all of it and to see Depends on. Read the orange "Needed by" line. If the text is missing, strange, or mentions something you use, skip the app.
  6. Tick only three to five apps. A short batch is easy to test and to undo. Do not use Select shown on a long list.
  7. Prefer Disable when unsure. Disable keeps the app on the phone, only switched off, and is the lightest change. Uninstall for your user is stronger. Neither frees much storage for a system app (its file stays on the protected system part). The gain is less background activity and a tidier phone.
  8. Read the review sheet and confirm. Check the results are all Success.
  9. Test the phone. Restart it. Then check: a call, a text message, the camera, Wi-Fi and mobile data, Bluetooth, the keyboard, fingerprint or face unlock, notifications, an alarm, charging, and anything you use every day. Use the phone normally for a day.
  10. Keep a record. History lists what you did, and Copy Log copies it as text, which you can paste into a note. Before a batch you can also use Save to List, so you have the names later.
  11. Repeat with the next small batch. Only when you are comfortable with Recommended should you look at Advanced, and then one app at a time.

Putting one app back

  1. Open the UAD-NG Debloater tab. Set State to Uninstalled (for an uninstalled app) or Disabled, or to All. Turn all the level chips off, so that every level is shown.
  2. Find the app (use the search box) and tick it.
  3. Tap Restore, check the review sheet, and confirm. An uninstalled app is reinstalled from the phone's own storage, a disabled app is enabled.
  4. Other ways: open History and tap Undo on the entry that removed it, or open the app's menu in the Application Manager (filter Uninstalled to find it), which offers Reinstall or Enable.

A restored app acts like a freshly installed one: its old settings and data are usually gone, and it may ask for permissions again.

What never to remove

There is no complete list, because every phone is different. These roles are essential on almost every phone. Do not remove, disable or uninstall an app that does one of these things unless the description clearly says it is safe and you have a replacement:

  • The system interface: the status bar, notification shade, lock screen and navigation (often called System UI).
  • The phone and calling parts, contacts storage, and the messages app if you use texts.
  • Settings, the app installer, and the permission controller.
  • Your home screen app (launcher) and your keyboard, unless you have already installed and chosen another one.
  • Google Play services and the Play Store, if you use Google apps; the Android System WebView, which many apps use to show web pages.
  • Anything for emergency alerts, SIM card, mobile data, Wi-Fi, Bluetooth, fingerprint or face unlock, and the camera.
  • Every app tagged Unsafe, and any app with a "Needed by" line that lists apps you use.

If the phone will not start: boot loop

A boot loop is when the phone restarts again and again, or stays on the logo, and never reaches the home screen. It happens when something the system needs at start-up is gone. Try these in order, and stop at the first one that works:

  1. Wait and restart. Hold the power button until the phone turns off, wait ten seconds, and start it again.
  2. If it reaches the home screen, even for a moment, open this app and use History then Undo on the last entry, or Restore the apps you removed.
  3. Safe mode. It starts the phone with only its built-in apps. How to start it depends on the phone: often you hold Volume Down while the logo shows, or press and hold Power off on the power menu. If the phone starts in safe mode, an app you installed is probably the trouble; restart normally afterwards. Safe mode does not undo a removal, and this app does not run in safe mode.
  4. Computer with ADB (advanced). If USB debugging was on, adb shell pm install-existing PACKAGE brings an app back. A phone stuck on its logo often does not allow this.
  5. Factory reset, as the very last resort. From the phone's recovery menu, choose to wipe data. This deletes everything stored on the phone but puts back the system apps you removed, because they never left the system part. You will need your screen lock and account passwords.
Tip. Because you only change a few apps at a time and restart after each batch, a boot loop almost always points to those few apps. Tell them to whoever helps you.

When a removal fails

A Failed row means the phone refused. Nothing changed for that app. Read the reply on the Debloater Results sheet; the tab adds a note for the common refusals (system app needing root, a device policy, a restriction). Choose Disable instead, or leave the app.

Install an app from a file on your phone: a plain APK (an Android app file), or a bundle (APKS, APKM, XAPK) made of several parts. The tab reads the file first and shows what it is, then lets you choose how to install it.

Where to find it: the fourth tab in the usual order, named APK Installer/Updater (the tab bar shows "Installer/" over "Updater"; switch it on in the Feature List if it is missing). At its top are two boxes, like the Terminal and the ADB Console: Application Installer on the left and Application Updater on the right. The tab opens on the Application Installer box every time you tap it. This section describes the Application Installer box; the right-hand box is described in Application Updater.

Before you start

  • Choosing and reading a file needs no working mode. Installing works in two ways: with ADB, Shizuku or Root (see Working modes) you get every option; with No privilege Android's own install screen asks you to confirm and most options are switched off. In that case Android can also ask you to allow installs from this app first (Android calls the setting Install unknown apps): switch it on for this app when asked, then press Install again if nothing happens. You can allow it beforehand: About, Permissions, then Allow on the row Install unknown apps (The permissions this app asks for).
  • The app first copies the file into its private cache and unpacks the parts, so keep free space of up to twice the file size. The cache is emptied after the install.
  • Only install files from sources you trust. An APK can do anything a normal app can.

Step by step

  1. Open the tab. The first time, the app also searches your storage for package files (see Find APKs below).
  2. Pick a file in one of three ways: Choose APK / APKS / APKM / XAPK (Android's file picker opens), a row in the found-files list (tap it), or Install XAPK (APK + OBB data) (the same picker, with a reminder that game data is copied afterwards). You can also open a package from another app and choose this app; press Always to make it the default installer. The tab then opens by itself, and switches itself back on if you had turned it off.
  3. The hint under the buttons says "Reading package..." and then, for example, "Loaded APK - review and install below." The page scrolls to a card with the app's name. More cards appear: VirusTotal scan, Splits (bundles only), Game data (OBB) (only when the file has some), and Install options.
  4. Read the package card (next table).
  5. Optional: scan the file with VirusTotal (below).
  6. Check Install options. The start values suit most files, and Authorizer (the part that carries out the install) is already set to your active mode. If no working mode is on, it starts on No privilege.
  7. Press Install. A message says "Installing ...". Below the button, a grey line shows the command that will run, for example pm install -r (1 file). With No privilege it says instead that a system install dialog will ask you to confirm.
  8. A result sheet opens, titled "Install" plus the package name, with the method used. On success it offers Launch Application, Application Settings and, for a file on your storage (for example one loaded from the found-files list, and only while Offer to delete the file afterwards is on), Delete the installer file. Press Done.

Many apps come as several files, not one. This page explains what that means, which file types the installer accepts, how it chooses the parts your phone needs, how game data is copied, and what to try when a bundle will not install.

Where to find it: in the Application Installer box of the APK Installer/Updater tab, in the Splits and Game data (OBB) cards. They appear only when the file you picked has those parts.

What a split APK is

A simple app is one APK file. A split app is cut into parts: a base APK (the core of the app) and extra files for one thing each. Most extra files are config splits, made for one processor type (for example arm64-v8a), one screen density (for example xxhdpi) or one language (for example en). Others are feature modules, optional parts of the app. All parts of one app must be installed together, in a single step.

Developers do this to keep downloads small: Google Play sends each phone only the parts it needs. When you get an app outside Play, those parts are packed into one file called a bundle.

Which files the installer accepts

TypeWhat it is
APKOne app file.
APKSA bundle made by Google's bundletool and similar tools: a ZIP file of APKs.
APKMThe bundle format of APKMirror, also a ZIP file of APKs.
XAPKA ZIP with one or more APKs, a manifest, and usually game data (OBB) files.

The app decides by the file's content, not its name. If the file opens as an installable APK, it is an APK. If not, it is opened as a ZIP of APKs, and called XAPK if it has an XAPK manifest or game data, APKM if it carries APKMirror's info file, and APKS otherwise. After picking, the hint says "Loaded APKS", "Loaded XAPK with 2 game data files" and so on. A file with no APK inside shows "Could not read that package: no APKs found inside this archive". A very large file (over 8 GB) is refused as too large to be an app package.

How it picks the parts for your phone

The app asks the phone for its processor types (best first), its screen density, and its language list. Then it ticks:

  • CPU: one split only, the first type on your phone's list that the bundle has. The note reads "fits this phone (CPU arm64-v8a)"; the others read "another CPU". If no CPU split fits, none is ticked, and you may need another build of the app.
  • Screen density: the one Android itself would use for your screen, usually the closest. The rest read "another screen density".
  • Language: every language in your phone's language list (Settings, Languages). The rest read "another language". English is not added if it is not on your list.
  • Feature modules and other extras are not ticked: the note reads "feature module (optional)", "for a feature module" or "optional extra".

The line under the Install button shows how many files will go in, for example pm install-multiple -r (4 files).

Careful. Some apps need a feature module just to start. If the app crashes at once, or the install says a split is missing, press Select all and install again.

When you send a bundle to another device in the Connected Devices tab, the app picks the parts for that device by its own rules, not these: it always sends the feature modules too, and it adds English. See Sending apps to the device.

Signing and splits

Every part must be signed with the same key. A bundle you downloaded from its maker or from APKMirror already is. The signature line on the package card is read from the base APK. If you edited a bundle, its signature can no longer be checked; the card then says so, and Android may refuse it. Installing from the File Manager signs a copy for you. See APK Installer/Updater for the two Block switches.

Game data (OBB)

Big games keep their data outside the APK. In a bundle, those files live in folders such as Android/obb/PACKAGE/ (sometimes Android/data/PACKAGE/). When the file has some, the Game data (OBB) card lists each one with its destination, for example /sdcard/Android/obb/PACKAGE/, and its size.

  1. Keep the switch Copy data files after install on (it is on at first).
  2. Press Install. The app installs the parts first.
  3. Only if the install succeeded, a line shows "Copying data file 1 of 2: ... (1.2 GB)..." for each file.
  4. The result sheet adds "Game data (OBB):" with, for example, "2 of 2 data files copied (1.2 GB) to Android/obb/PACKAGE/".

On Android 11 and newer, an app cannot write into Android/obb or Android/data itself, so the copy needs ADB, Shizuku or Root. With No privilege you may see "Android doesn't let this app create that folder without ADB, Shizuku or Root. Copy it by hand to ...". Only files whose folder names the same package as the app are copied, and unsafe paths are refused. A multi-gigabyte copy takes time: keep the phone awake and plugged in. Free space is needed twice: the app keeps a copy of the bundle in its own cache while it works, and then the final files are written as well.

If the data copy fails, the app is still installed, but the game may ask to download its data. You can open the file in the File Manager without unpacking it and copy the data folder by hand (see Archives).

Several packages

The installer takes one package at a time, but all its ticked parts go in together. To install many apps, load one, install it, then load the next from the found-files list. While an install runs, another cannot start ("An install is already running").

If a bundle fails

  1. Read the result sheet and match it with the error table in APK Installer/Updater.
  2. Press Select all and try again. If it works, the app needed a part that was not ticked.
  3. Press Match this phone and look for a row marked "fits this phone (CPU ...)". If there is none, the bundle may not support your phone.
  4. Check free space. Try a different Authorizer, for example ADB instead of No privilege.
  5. "no APKs found inside this archive" or "could not read the base APK of this package" usually means a damaged or incomplete download. Download it again.
  6. If the app is already installed with another signing key, uninstall it first. Back up what you need.

The + tab: add a store of your own

The last tab of the row is a +. Tap it to add one more place to find apps. Paste an address:

  • An F-Droid style repository, such as https://apt.izzysoft.de/fdroid/repo (the address of the folder that holds index-v2.json or index-v1.jar; with or without the file name, and the app also tries the address with /repo added). The app first reads the start of its index to check that it is a repository and to learn its name. It then lists all its apps like the F-Droid tab does, with the build that suits your phone, and checks every download against the repository's own hash.
  • A GitHub or Codeberg project, such as https://github.com/owner/project: a tab with that one project, which installs the APK of its latest release.
  • A GitHub or Codeberg user or organization, such as https://github.com/owner: a tab with every project of theirs that is not archived and not a fork (up to 300 on GitHub, 200 on Codeberg), sorted by stars. Not every project publishes an APK; Install says so when a project has none.

Up to 12 extra stores; they are kept on this phone and come back after a restart.
