Browse the files and folders on your phone, read and edit text files, copy, move, rename, delete and share things, and look inside zip files. You do not need a computer.

Where to find it: the tab named File Manager, next to APK Installer (you can move or hide tabs in Feature List).

Before you start

Most of this tab works on your own storage and needs no working mode (a way for this app to run commands with more rights than an ordinary app: ADB, Wireless Debugging, Shizuku or Root). It needs permission to see your files instead.

PlaceWhat it needsWhat you can do
Your storage, /storage/emulated/0 (Download, Pictures, DCIM and so on)All-files access (a switch in Android's settings that lets an app see all your files; Android 11 and later) or the storage permission (Android 10 and earlier)Everything on this page
System places such as /system or /data/local/tmpA working modeLook, read, and change what that mode is allowed to change
An SD card, a USB drive or another app's folderNothing extraAdded with + Add storage: see SD cards, USB drives and other storage

With no working mode (Read-Only) the tab still works on your own storage once All-files access is on. See Permissions.

Open the tab and find your way

  1. Tap File Manager. The list shows your storage folder. If a box says Storage looks inaccessible, tap Grant storage access. Android opens its All files access screen for this app (on Android 10 and older it shows a storage permission box instead): switch it on or allow it, press Back, and the list fills in by itself.
  2. Tap a folder to open it. Folders come first, then files. The row at the very top, .. with the words Up one folder, goes one level back up.
  3. To jump somewhere, type a path in the box under the title (it starts as /storage/emulated/0) and tap Go. /sdcard works too. The small path above the list shows where you are.
  4. Tap a file to see what you can do with it, or press and hold a row to select things (both below).

Each row has an icon (a small picture for photos and videos), the name (folder names end with a slash) and a grey line such as -rw- • 1.2 MB. A first letter d means a folder. The other letters say what this app may do with it: r read, w write, x run (for a folder: enter). For system places listed through a working mode you see the longer form that the ls command prints, such as drwxrwx--x. The button with three dots at the right of a row opens the same actions as tapping a file, for folders too.

Under the path box are shortcuts: Storage, /data/local/tmp and /system (these two need a working mode), + Folder and + File (make a new one here), Refresh and Select. Storages you add appear in the row above them.

Viewing and editing

  • Text. View shows the first 128 KB in the sheet, with colours for code and settings files (.xml, .json, .py, .sh, .prop and more). A file that is not text shows as unreadable characters: use Open with... instead.
  • Pictures (jpg, png, gif, webp, bmp, heic, heif, avif) open with Fit / actual size. PDF files show one page at a time with Previous and Next. Fonts (.ttf, .otf, up to about 6 MB) show a sample sentence.
  • Video and music have no player in this app: View hands them to Open with....

To change a text file:

  1. Tap the file, then Edit. A tall editor sheet opens. A file over 2 MB is refused (too big to edit here), and so is one that is not text.
  2. Type your changes. The line at the bottom says Unsaved changes, counts characters and shows your line and column.
  3. Tap Save. The line says Saved. The text goes to a temporary file first and is swapped in only when that worked, so a failure keeps the old text. Line endings are kept.
  4. Tap Close. If you have not saved, the app asks Close without saving your changes?

Wrap lines and Colors are two tick boxes at the top of the editor (both on). If something else changed the file while you were editing, Save asks whether to save your version over it. A new text file made with + File opens here at once.

Copy, move or delete several things

  1. Press and hold one row for half a second, or tap Select. A bar appears: 1 selected, with All, Copy, Move, Compress, Delete and a close button. Tap rows to add or remove them. All picks everything in the folder; tap it again to clear.
  2. Tap Copy or Move. A bar says 3 items to copy: open the target folder, then tap Paste.
  3. Open the target folder. The bar stays while you browse.
  4. Tap Paste here. If a name is already used there, a box titled A name is already taken asks what to do. Tapping outside it cancels the paste.
ChoiceA name that is already taken
ReplaceThe new item goes over the old one. Two folders with the same name are merged.
SkipThe old one stays. The item counts as skipped.
Keep bothThe new one gets another name, such as photo (1).jpg.

For Delete, tap it in the selection bar and confirm in the box that lists the first names. Folders go with everything in them.

Progress, the notification and Cancel

While a job runs, a line above the list shows where it is, for example Copying 2 of 5: movie.mp4 - 45% · 4.2 MB/s · 8 s left, with a Cancel button. The same text is in a notification called Copying 5 items, with a progress bar and its own Cancel. The notification keeps the job alive if you leave the app (on Android 13 and later, allow notifications to see it). If nothing moves for 20 seconds the line says so.

Cancel stops the job soon and the result says stopped. A copy that is stopped never leaves a half-written file under the real name. Only one file job runs at a time (A file job is still running). At the end you get a message such as Copied 5 of 5, with counts of skipped and failed items, and a box lists each failure with its reason. Moving inside one storage is instant; moving to another storage copies first and then removes the original. Jobs on places this app cannot write itself go through the working mode and show no speed or time left.

New folder, new file, rename

  • + Folder and + File ask for a name. A name cannot be empty, hold a slash, or be . or .., and names that differ only in capital letters count as the same (That name is already used here).
  • Rename shows the name in a box: change it and tap Confirm. The ending (such as .txt) is just part of the name: changing it does not convert the file.
  • Copy and Move in the sheet ask for a destination path, filled in with the item's own path. Change it to a folder that already exists, for example /storage/emulated/0/Download. A same-named item already there is replaced without asking, so for anything important use Select, Copy and Paste here (it asks what to do when a name is taken).

Options and order

  • Show hidden files (off): also lists names that start with a dot (file managers usually hide these). While it is off, a line at the end of the list says how many hidden items are not shown. The search uses this switch too.
  • Show thumbnails (on): small pictures for photos and videos on your storage (none for pictures over 80 MB or for added storage). They are cached, up to 48 MB; Clear thumbnail cache empties it.
  • The list is always folders first, then files, each in alphabetical order. There is no sort menu and no Properties screen. The size is under each name; to find the biggest or newest files use search with size: and date:.
Careful. There is no recycle bin. Delete removes a file, or a folder with everything in it, at once. In a file's sheet, Delete shows a red button Delete NAME? (with the real name), and one tap on that button deletes at once. There is no undo: the only way back is a copy you made earlier. Before deleting something you did not make, open it and check what it is.
Risky. With a working mode you can reach folders that belong to Android itself (/system, /data, /vendor). Renaming, moving or deleting things there can stop the phone from starting or make apps crash. First copy anything you might need to a safe folder. The app refuses to delete or move the root, a top-level folder, a whole storage or a system tree (System location: not touched), but the files inside them are not protected. If the phone no longer starts normally, you may need a computer or a factory reset: see Troubleshooting.

Find a file by part of its name, its ending, size, date or kind, by words inside it, or by the names inside zip files. The search is part of the File Manager.

Where to find it: in the File Manager, the box that says Search files and folders (under the path box), with the Search button next to it.

Before you start

The search is done by this app itself, not through a working mode. It therefore needs All-files access to see your storage (the app asks when it is missing, unless a working mode is on); a working mode alone does not help, because the search reads the files itself. In storage you added yourself (see SD cards and other storage) it needs nothing extra.

Step by step

  1. Choose where to look in the drop-down next to the tick boxes. It starts as This folder. The other choices are Internal storage, Downloads, Camera and photos, Pictures, Documents, Music and Movies (only those folders that exist), SD card or drive with a code when the phone shows one, and Whole phone.
  2. Set the two tick boxes. Include subfolders (on) looks in every folder below; off, it looks only at what is directly in the folder. Search inside archives (off) also looks at names inside zip files.
  3. Type what you look for and tap Search (or press Enter). If the box is empty you see Type what to search for.
  4. Watch the line Searching /storage/emulated/0/Download · 1200 looked at · 3 found. The Search button becomes Stop, and the line has a Cancel button.
  5. The results replace the folder list. A line says how many were found and how long it took, for example 12 found · 0.8 s. Tap Back to the folder to return.

You can type plain words, or add the special words below. Several parts together all have to fit: report ext:pdf date:30d size:>1mb. Tap Search help for a short reminder on screen.

Reading the results

Each result shows the name, where it is (for an archive entry: the archive, then the entry), the size and the date, and, for a content: search, the first matching line with its line number. Tap a result:

  • a file opens the same sheet as in the folder list (View, Edit, Share, Rename...);
  • a folder opens that folder;
  • an archive entry opens the archive and puts the entry's name in its search box.

The In folder button at the right of a result closes the results and shows the folder that holds it. After you rename or delete something from the results, the search runs again by itself.

The pills above the results

A row of pills sorts the results: All, Images, Video, Audio, Documents, APKs, Archives, Folders, Over 10 MB, Over 100 MB, Last 7 days, Last 30 days. They work on the results you already have, by the ending of each name.

  • The kinds combine with "or": Images and Video together show both.
  • Size (10 or 100 MB) and age (7 or 30 days) take one choice each: tapping the other one swaps it.
  • A kind, a size and an age all have to fit at once.
  • With two or more pills on, a line says what is shown, for example Showing Images or Video, Over 10 MB., with a Clear filters button. The count adds how many are shown. All turns every pill off.

Searching an SD card or other added storage

Open the added storage first, then leave the drop-down on This folder. Names, endings, kinds, sizes, dates and content: (text files up to 4 MB) all work there. archive: is skipped, with a note saying so, and Search inside archives does nothing there.

What is not searched, and how long it takes

  • Names inside archives are searched only with archive: or the Search inside archives tick box, and only in zip-type files (zip, apk, apks, apkm, xapk, jar, aar, epub, docx, xlsx, pptx and similar). The inside of 7z, rar and tar files is never searched. With that tick box on, content: also reads text entries up to 1 MB.
  • content: reads only text files up to 4 MB. Pictures, videos, music, archives, empty files and files that are not text are skipped.
  • Names that start with a dot are skipped unless Show hidden files is on. Links to folders are not followed, and the system folders /proc, /sys and /dev are skipped.
  • Files and folders this app is not allowed to read are skipped without a message.

The search does not go deeper than 40 folder levels. It stops by itself at 1000 results, after 400,000 files and folders looked at, or after 90 seconds, and the line then says stopped at the limit. Tap Stop (or Cancel) to stop earlier: the line says stopped and the results found so far stay. Only one search runs at a time (A search is still running).

Tip. Name searches are quick. content: and archive: searches open files and are slow on a big storage. Make them smaller: choose a folder in the drop-down instead of Whole phone, and add ext:, type:, size: or date: to cut down the files that have to be opened.
Nothing found? Check the drop-down (the folder you are looking at, or all of storage), whether the word is in a hidden name (turn on Show hidden files), and whether All-files access is on. Capital letters never matter, but spelling does.

An archive is one file that holds many files (a zip file is the best known). The File Manager can look inside one without unpacking it, unpack all or part of it, make new ones, and change what is inside some of them.

Where to find it: tap an archive in the File Manager, then View contents, Extract... or Open as archive. To make one, select files and tap Compress.

Before you start

This works on files the app can read itself (your storage with All-files access) and, through a copy, on added storage. Changing an archive needs a folder this app can write to. No working mode is needed for your own storage.

Look inside an archive

  1. In the File Manager tap the archive. In the sheet tap View contents. For a file that does not look like an archive, tap Open as archive; if it is not one you see Not a readable archive.
  2. The folder list is replaced by an archive card. At the top: the name, and a line such as 12 files • 3.4 MB • 7Z (solid: files are packed together) • password-protected, then where the archive is. Under it: a search box (Search inside the archive...), a path trail you can tap, and the buttons Up, Extract this folder, + Add file, + Folder, Compare (and Sign for an .apk).
  3. Tap a folder to go in. Each row says the size and, for files, 42% packed (or stored, or encrypted) and the date. Long lists show 400 rows; tap Show more for the rest. A search shows at most 5000 matches.
  4. Tap a file for its sheet. View shows text with colours (first 256 KB), a picture (up to 4 MB), an app's compiled XML turned back into readable XML (read only), or, for anything else, the first 512 bytes as hexadecimal numbers (a plain way of writing raw data). A line shows size, packed size, CRC (a check code for the contents) and date.
  5. Tap Close at the top right to go back to the folders. Open inside opens an archive that is inside this one; that one is view only.

Extract

  1. Tap Extract... in a file's sheet (the whole archive), in an entry's sheet (that file or folder), or Extract this folder in the archive card.
  2. In Extract into choose This folder (where the archive is), A new folder named after the archive (the starting choice), or Another folder (type its full path).
  3. Under If a file is already there choose Replace it, Skip it or Keep both (the starting choice: the new file becomes name (1).ext).
  4. Optionally tick Delete the archive afterwards (whole archives on your storage only). The app asks again, and deletes it only if every file was extracted with nothing skipped.
  5. Tap Extract. A progress line with Cancel and a notification show speed and time left. At the end: Extracted 12 files (3.4 MB) to /storage/emulated/0/Download/photos. Names that are unsafe (for example ones that climb out of the folder) are skipped and listed.

If the folder is not writable for the app you see This app can't write to ...: choose a folder on shared storage.

Passwords

A box called Password needed asks when an archive or one file in it is locked. Type it (tick Show the password to check it) and tap Open, Extract or Unlock. A wrong one gives That password did not work. Try again. The box says the password is used only for this archive, only while it is open, and is never saved. A zip opens without a password; only the locked files ask. A 7z or rar with locked names asks before it opens.

Make an archive

  1. Select the files and folders (see File Manager) and tap Compress, or tap Compress... in the sheet of one item. Added storage does not offer it.
  2. In the Compress box set the name, the Format (Zip opens everywhere; 7z packs smallest; the tar formats; the single-file formats appear only when one file is picked), and Packing: Store (none, fastest), Fast, Normal (starting choice) or Maximum.
  3. For zip or 7z you can add a Password. For zip choose Protection: AES-256 (strong, the starting choice), AES-128 or ZipCrypto (weak but opens everywhere). 7z always uses AES-256 and hides the file names too.
  4. Choose Save into (this folder or another full path) and what to do if the name is taken (Keep both or Replace it), then tap Compress.
  5. The result reads like Created photos.zip (12 files, 3.4 MB to 2.1 MB, password-protected).
Careful. If you lose the password of an archive, the files cannot be recovered. Write it down somewhere safe.

Change what is inside

For zip, 7z and tar archives, the entry sheet has Edit text (plain UTF-8 text up to 256 KB, with the same kind of line ending all through), Rename / move (change the folder part of the path to move it) and Delete; the card has + Add file (type the path of a file on storage, then the name to give it inside) and + Folder. The archive is rewritten next to the original and swapped in only when that worked and the result can be read back, so a failure keeps the original.

It is refused for installed and system packages (under /system, /vendor, /data/app and similar: copy the file to storage first), for archives opened from inside another archive, and for files with extra data in front of the archive (such as self-extracting ones). rar and single compressed files cannot be changed: if the buttons show, an attempt ends with This archive can't be edited here. Compare lets you check two archives, or an archive and an installed app, entry by entry.

Careful. Changing an .apk breaks its signature, so Android will not install it until it is signed again. The app asks before the first change and then shows a red banner with Sign it now.... The signature uses a key made on this phone; an installed app signed by someone else cannot be updated with it, and removing the installed one first deletes its data. There is no undo for an edit: copy the archive first.

Big archives

  • Opening reads only the list of names, so it is quick even for a big file.
  • In a solid 7z or rar, or a compressed tar, reading one file means unpacking the ones before it. Extracting everything is faster than many single files.
  • One archive job runs at a time (Another archive job is still running). Make sure there is free space for the result.
  • A file on added storage is first copied into the app's cache (up to 300 MB). Open inside and Install refuse a single entry over 2 GB: extract it instead.
  • If the app cannot read the file itself, it copies it through the working mode first (up to 3 GB).
If it fails. Not a readable archive: the file is damaged, cut short, or not an archive. That password did not work: type it again (a damaged archive gives the same message). This file changed after it was opened: close the archive, open it again and repeat the change.

Add an SD card, a USB drive or a folder that another app shares (Termux, or a cloud app that offers its files to Android, for example), so the File Manager can work on it. You do it once, through Android's own picker.

Where to find it: File Manager, the row of links under the options, button + Add storage.

Why Android asks you to pick the folder

Android does not let an app open any folder it likes on a card, a drive or another app's space. It must be given a folder by you, in a system screen (the Storage Access Framework). The app then holds that one folder only. This needs no working mode, no root and no All-files access.

Tip. On some phones, once All-files access is on, a card can also be opened by typing its path, /storage/ followed by a code like 1A2B-3C4D, in the path box. The search drop-down lists such a card as SD card or drive. If that works for you, you may not need + Add storage. If it does not work, or you want to reach a drive or another app's folder, add it as below.

Add a storage

  1. Plug in or insert the card or drive. In the File Manager tap + Add storage.
  2. Android shows its own file picker (its look differs from phone to phone). Open its side menu, choose the card or drive, then use its button that allows access to this folder (often Use this folder and then Allow).
  3. The File Manager opens the storage and a button with its name appears in the row, with an X next to it. The grant stays after you restart the app.
  4. Tap the name button at any time to come back to the top of that storage. Inside a folder, the .. row goes one level up; the top of a storage has no such row. The name on the button is the one Android gives the storage (for a card it can be a code such as 1A2B-3C4D).

Type commands to your phone and read the answers, in one of three shells. A second pane, the ADB Console, is the older command box of this app. Coding assistants are covered in Coding agents in the terminal.

Where to find it: the tab named Command-Line Interface. Two big buttons at the top, Terminal and ADB Console, switch between the panes; the tab remembers the one you used last.

Before you start

A command is a line of text that tells the phone to do one thing. A shell is the program that reads your lines and runs them. Which shell you pick decides what the commands may do. Pick it with Shell above the screen. Words such as ADB and root are explained in the Glossary.

Termux is a separate free app that gives you a full command line (bash is its shell, and pkg installs programs into it). The first time, the tab picks Termux if it is set up, otherwise the working mode if one is connected, otherwise the sandbox (you can change that in the gear, under Shell when the Terminal opens). Each shell has its own screen and stays open while you use other tabs, so cd (change folder) and variables carry over. Restart shell starts a fresh one.

Next to the drop-downs at the top (Coding Agents, Model, Effort) are three small buttons: the gear (Terminal settings, which holds your keys and defaults), MCP and Help (a short explanation of the Terminal inside the app).

Run your first command

  1. Open the Terminal pane. The black screen prints a welcome and a line saying which shell is ready, for example sh ready through ADB, running as the shell user (uid 2000) in and a folder. The uid is the user number: 2000 is the ADB shell user, 0 is root.
  2. Tap the box at the bottom, type getprop ro.product.model and tap RUN (or Enter on the keyboard).
  3. Your line is echoed as folder $ command and the answer appears under it: the model name of your phone. The prompt shows # instead of $ when the shell is root.

Typing, keys and history

  • RUN sends the line. While a command runs it turns into STOP. The small button at its left shows $ (or #): it switches between commands and the AI chat of an agent, and is dim until you pick one.
  • The key rows under the box work like Termux's: ESC clears the line, TAB completes a file name (several matches are listed), CTRL stops what is running, the up and down arrow keys go through earlier commands (the last 120 are remembered), the left and right arrow keys, HOME and END move the cursor, and | / - ~ are there because phone keyboards hide them. SHIFT swaps the row for a second row of symbols: backtick, $ ; : " ' \ { } ( ) * & #. Tap SHIFT again to go back.
  • Suggestions. While you type, a faint grey completion shows on a line just above the box (the part you have not typed yet, after what you have). It comes from your earlier commands first, then from the packages on your phone (after pm, am, dumpsys and similar commands) and a list of common commands. Press the right arrow key with the cursor at the end of the line to accept it, or tap the suggestion line (phone keyboards often have no right arrow). Keep typing to ignore it. It only suggests; nothing runs until you tap RUN.
  • clear empties the screen. exit ends the shell; press Enter to start a new one.

Set up Termux

Open the gear, then Termux setup (it also opens by itself when you pick Termux and it is not ready). It lists five steps and puts a tick on each one that is done (the second step never gets a tick):

  1. Install Termux from F-Droid (a free app store for open-source apps) or GitHub. The old Google Play build is not suitable.
  2. Open Termux once, so it finishes installing itself.
  3. Let Termux take commands from other apps: tap Copy, open Termux, paste and run the line shown (it adds allow-external-apps=true to Termux's settings).
  4. Allow this app: Android asks whether this app may Run commands in Termux environment.
  5. Test the connection: Test sends a harmless command and says Termux answered.

Then tap Use Termux as the shell. Sync with Termux makes this shell match your own Termux: it starts the Termux shell again, reads your aliases, functions and exports from ~/.bashrc (also when that file starts with the usual "only for interactive shells" line) and prints what it took over: the bash version, home folder, package folder, how many aliases and functions, and whether phone storage is set up. Set up storage in Termux opens Termux and runs termux-setup-storage only when phone storage is not set up yet (Android may ask you to allow it); when it is, Termux just says so and nothing is rebuilt.

Set up Termux now (the same sheet, enabled once Termux is installed and allowed) is the one-tap setup of a working command line. It runs these steps in the Termux shell, where you can watch each one: update the package lists (pkg update), install vim, nano, git, python, openssh, curl, wget and htop (pkg install), write a starter ~/.bashrc, ~/.vimrc and ~/.nanorc, and check that each tool is there. Choose tools lets you tick others (tmux, ripgrep, jq, zip, unzip, rsync, nodejs, clang, make, man) or leave some out, and turn any of the three starter files off; the choice is remembered. Then tap Open the real terminal to use them.

The starter .bashrc gives you a colour prompt that shows the folder and the git branch (and turns its $ red after a command that failed), a long history shared by all your terminals, aliases (ll, la, .., gs, gl, py, sd for shared storage, dl for Downloads, update), and small helpers: mkcd (make a folder and go in), extract (open any archive) and serve (share the current folder over HTTP). The .vimrc turns on syntax colours, line numbers, the mouse and four-space tabs; the .nanorc line numbers, the mouse and syntax colours. Only a marked block is written (it starts with # >>> ADB App Manager starter >>>): your own lines above or below it stay, and running the setup again replaces the block instead of adding a second one. If you have no ~/.bash_profile, one is made so that login shells (the real terminal's) read ~/.bashrc; if you have one, it is left alone. If a step fails (no internet, for example), the setup stops there and says which step; run it again when it is fixed, the finished steps are quick the second time.

The real terminal (full screen)

The line-based Terminal cannot run programs that draw on the whole screen. Real terminal (the button below the screen) can: it runs your shell on a genuine pseudo-terminal, as Termux does, so vim, nano, top, htop, less, ssh, a Python prompt, colours, the arrow keys, Ctrl-C and window resizing all work. It covers the whole app, follows the on-screen keyboard, and keeps what you did when you close it with the X or Back (the session goes on until you type exit or tap Restart; after exit, press Enter to start a new shell).

  • Shell (top left): This app (sandbox) is Android's own shell in this app's folder, with only the tools Android has (toybox): no vim or nano. Working mode is a shell with the power of ADB, Shizuku or Root (for ADB it is the phone's own adb shell on a terminal). Termux is Termux's bash with everything you installed there with pkg, vim and nano included; it needs the Termux set-up of the Terminal's settings. Changing the shell restarts the terminal.
  • Keys (bottom): ESC, TAB, the arrows (hold to repeat), HOME, END, PGUP, PGDN, / and −, a row of symbols (| ~ $ ; : " ' \ { } [ ] ( ) < > * & # = + _ ? ! @ % ^ . , and the backtick), FN for F1 to F12, and the keyboard key that shows or hides the keyboard. CTRL and ALT are sticky: tap once and the next key you type gets it (CTRL then c is Ctrl-C); tap twice to lock it (it shows a line under it), a third time to free it.
  • A− and A+ change the text size (remembered). Copy copies the selected text, or with nothing selected the whole screen. Paste types the clipboard in. Restart ends the session and starts a new one.
  • Behind it is a small helper program that comes with the app (libptyexec.so), for 64-bit and 32-bit phones; Android does not let an app open a terminal by itself.

The ADB Console pane

  • A card shows the active working mode, with Configure and Working Modes, and buttons Rish mode (a long-lived Shizuku shell where cd sticks), UID (id), Connect 5555, tcpip 5555, Dev Options and Cheat Sheet. See Working modes.
  • Each command is run on its own through the active mode, so cd does not carry over (Rish mode does). Without a working mode the commands run as this app, like the sandbox.
  • Find in output... highlights matches (2 / 7 matches) with arrows to jump; Copy puts the whole output on the clipboard and Share sends it as a text file.
  • Suggestions. The ADB Console completes as you type, the same way the Terminal does: a grey line above the box shows the rest of the command, from your history first, then from the packages on your phone and a list of common adb/shell commands. Right arrow (cursor at the end) or a tap on the line accepts it. Nothing runs until you tap Run.
  • History lists the last 80 commands (tap one to edit it, Run, Save, or the X). Saved keeps named commands or several-line scripts; Pin turns up to six into one-tap buttons.

If it fails

  • No working mode is connected: connect ADB, Shizuku or Root first: tap Working Modes in the message, or choose another shell.
  • Termux is not installed or This app may not run commands in Termux yet: follow Termux setup above.

  • The shell is not running: press Enter to start it again, or tap Restart shell.

A coding agent is an AI assistant you chat with inside the Terminal. It can suggest commands, read files and propose changes to files. You approve each step before anything runs.

Where to find it: Command-Line Interface, Terminal pane, the drop-down Coding Agents at the top. Choose None to use the Terminal on your own.

Risky. An agent can be wrong, and it runs commands with the rights of the shell you chose. In the working mode shell or as root, one command can remove apps, erase data or change settings. Read every command and every file change before you press Run or Apply. Do not press Always allow in this chat unless you are ready to accept whatever follows. Before you start, make a backup (App backups). Commands cannot be undone; only file changes can (/undo).

Before you start

  • The agent works in the shell you picked. The sandbox is the safest to try.

Add an API key

  1. Open the Coding Agents drop-down and choose an agent under API Key Required. If it is not connected yet, a sheet named after the agent opens (for Gemini, Claude, ChatGPT and Cursor it has two tabs: API key and Sign in with subscription; stay on API key for these steps).
  2. Tap Get a key. The provider's website opens. Create a key there (a long secret text, like a password). The provider may ask for billing details.
  3. Come back, tap the key box and paste the key. Tap Show to check it.
  4. Tap Test and save. The status says Testing.... The app sends one small request to the provider with your key, asking for its list of models. If it works, the key is saved, the sheet closes and the screen prints [Claude (Anthropic): it works, 8 models].
  5. If it fails, a sheet titled with the agent's name and the test failed gives the reason (for example The key was not accepted) and the exact reply, with Try again, Save anyway and Copy details. Use Save anyway only if you are sure the key is right and the test itself failed.
  6. To remove a key later: open the agent's sheet and tap Forget the key, then confirm. The gear lists every key as key sk-ant-...a1b2, with Change.

How the key is kept. Each key is encrypted with AES-256-GCM (a strong standard way of scrambling data) under a key held in the Android Keystore (Android's protected store for secrets), and kept in this app's private settings. App backups are off, so the key is not copied into a phone backup. The screen you see never gets the key back; only the start and the last four characters are shown. The app adds the key to a request itself, and only when the request goes to that provider's own address (or, for your own server, the address you saved with the key). If the Keystore is reset, the sheet says it can no longer be read: enter it again.

Model and effort

Model lists the provider's models. The list is read from the provider after a key works (at most once a day, or when you type /models); until then a short built-in list is shown. Effort is Low, Balanced (the starting choice) or High: how hard the agent is asked to think. Higher is slower and uses more of your paid quota. It changes anything only for Claude, ChatGPT, Gemini and Grok chatting through a key.

Chat with an agent

  1. Pick the agent. The small button left of the input switches to AI and the button says SEND. The state line under the Shell box shows the agent and, after a reply, how many tokens (pieces of text) were sent and received, for example 1.2k in / 300 out.
  2. Type a request, such as Which of my apps use the most storage?, and tap SEND. The answer streams in after claude › (the agent's name).
  3. Start a line with ! to run it yourself as a command (!ls). Lines starting with / are chat commands: /help, /new (start over), /undo, /stop, /agent name, /model name, /models, /effort high and /settings.
  4. Tap STOP to end the reply, and the command it started. New chat forgets the conversation.

Privacy: what leaves the phone

  • Every message you type, and the earlier messages of the conversation.
  • A short description of your phone: Android version, make and model, processor type, the folder you are in, and today's date.
  • What the agent reads or runs: the lines of files it reads and the output of commands it runs. Long output is shortened, and text that looks like an API key is hidden.
  • Nothing else of your files is sent unless a step reads it. The requests go from the phone straight to the provider; this app has no server in between.
  • Gemini's free tier: Google may use what you send to improve its products. Cursor's cloud agents receive your last few messages. An address that starts with http:// is not encrypted on your network. Ollama on the phone stays on the phone.
  • The conversation is kept on the phone (the last 60 messages) so it survives a restart. Turn Keep the conversation between launches off, or tap Clear the conversation, to remove it.

See also Privacy. Never ask an agent to read files that hold passwords or private data.

Logcat is the phone's running diary. Android and every app write short notes into it all the time: what they are doing, warnings and errors. The Logcat Viewer lets you read it, filter it and save or share it, which is the best way to find out why an app crashes.

Where to find it: the tab named Logcat Viewer. An app's own menu also has a Logs button that opens this tab for that app (see The app menu). For the log of another device, such as a watch, see Connected Devices.

Before you start

Reading the log needs a working mode (ADB, Wireless Debugging, Shizuku or Root). Without one you see Working Mode Required (Read-Only mode cannot read it). Opening the tab starts reading right away.

  • the tag in bold: who wrote it (an app part or a system part, for example AndroidRuntime);
  • the time, as hours, minutes, seconds and thousandths;
  • two numbers such as 1234/1250: the process id and the thread id (who ran the code; a process is one running program);
  • the message underneath. A message of several lines, such as the list of steps in a crash, stays together as one entry.

Record to a file and look at it later

Live logs scroll by too fast to read. Record to file writes everything to a file on the phone while you use the app, whether or not the Logcat tab is open, and then lets you open it as a still picture. It records what the view is set to: the level, the filter text and the app you picked.

  1. Set the Level (Error is a good start for a crash), pick the app if you like, and tap Record to file. A message says Recording the log to a file and the button becomes Stop recording with a count of lines.
  2. Use the phone until the problem happens. Every couple of seconds the new lines are added to the file; a line is written once, however often it appears in the phone's buffer. A recording stops by itself at 25 MB, and says so.
  3. Tap Stop recording. The file is kept and opens at once as a still picture. Open it again later with Recordings.

The still picture never moves. It has a search box (the match is marked), the colour key (tap a level to hide it), pages of 500 entries with Start, Earlier, Later and End buttons and a count such as 1-500 of 1200, and tapping an entry opens it in its own window with Copy, Ask agent and Web search. Copy shown copies the entries that pass the search and the key; Save writes the whole recording to Download/ADB App Manager (see Save above); Share sends it; Delete removes it. Only the last 4 MB of a very long recording are opened.

A recording lives in the app's own storage (it is removed when the app is uninstalled). Recording needs a working mode, like reading the log. If the app is closed by Android while it records, the recording ends where it was and keeps what it had; the next time you open the tab a message says it stopped. The file may contain personal details just like the log: read it before you share it.

Tap an entry to open it

Tap any entry (a coloured row) and it opens in a window of its own, so a long line is easy to read in full. Selecting text in a row with a long press still works and does not open the window. The window shows the level, the tag (the part of the system or the app that wrote it), the time and the process numbers, and the whole message in a box, with three buttons:

  • Copy: puts the entry's lines, as they were logged, on the clipboard.
  • Ask agent: asks your Default agent (Settings, under Language; with none chosen the built-in web lookup answers, free and without a key) to explain the entry in plain words: what it means, the likely cause, whether it matters and what to try. The answer appears under the buttons as it is written, with a Copy the answer button. This sends the entry's text (and your Android version and phone model) to that agent's company; nothing is sent until you tap the button. API keys that appear in the text are shortened first; other private details (account names, addresses) are not, so look at the entry before you ask. With no agent connected, nothing is sent to an agent: the built-in web lookup searches the web for the entry's name only and shows the matching passages, and the window offers to open the place where you set an agent up.
  • Web search: opens a search for the tag and the first line of the message in your browser. Long numbers and addresses are left out of the search so that other people's reports can match. It needs no agent.

Example: why does my app crash?

  1. Open the app's menu (Application Manager) and tap Logs, or open Logcat Viewer and use All apps to pick it. The log is now only that app's.
  2. Set the Level to Warn or Error, and Lines to 2000 so the crash does not scroll away.
  3. Optional: tap Clear so the log only holds what comes next. This empties the log for every app.
  4. Use the app until it crashes.
  5. Tap Pause. Scroll to the end and look for red E or F rows. A crash of an app written in Java or Kotlin has a row FATAL EXCEPTION, and all its lines have the tag AndroidRuntime: type AndroidRuntime in the filter and press Enter to see just the crash. (Filtering for FATAL EXCEPTION itself would hide the lines under it.) A crash of native code shows Fatal signal.
  6. Read the lines under it: Process: names the app, the next line names the error (for example a null pointer), and Caused by: lines name the real cause. The lines starting with at are where in the code it happened.
  7. Tap Share or Save and send the file to the app's developer.
Careful. A log can hold personal details: account names, addresses, the names of your apps. Read it before you share it, or filter it to one app first.

If it fails

  • Working Mode Required or reading logcat needs ADB, Shizuku or Root: set up a working mode.
  • (no matching log lines) or (no output): lower the Level to Verbose, empty the filter, or choose All apps. (When lines are already on the screen, a read that finds nothing leaves them there.)
  • Error-only views used to look empty or lose their lines after a second: the phone cut the last lines of the whole log before the level filter. The viewer now reads much further back for any filter and keeps what it has seen.
  • (name is not running, so there are no log lines to show): on an older Android the app has to be running; start it.

Your choice is remembered. A line above says how many processes were read (200 are shown at most).

  1. Open Processes. Each row shows the app's name and a line such as com.example.app • PID 4821 • 182 MB • 1.5% CPU. PID is the process's number; the memory is what it holds in RAM now.
  2. Rows for system and kernel work (names that are not an app) have no button. Rows for apps have a round X. Tap it to Force Stop that app: Stopped com.example.app. There is no question first.
  3. The list refreshes by itself. An app that restarts at once (a messenger, a clock) comes back.
Careful. Force Stop ends the app at once: anything not saved in it is lost, and its alarms and notifications may stop until you open it again. Its data is not erased. Do not stop a system app you do not recognise (the launcher, the keyboard, the phone app): the phone may misbehave until Android starts it again. To undo, open the app again. See The app menu for the same Force Stop.

CPU

The CPU is the phone's processor. The big number is how busy it was since the last reading, over all its cores (a core is one processing unit). The first reading shows 0% because two readings are needed. Under the graph:

  • One box per core with its own percentage.
  • Processor Information: SoC (the chip's name), Architecture, ABI (the kind of code it runs), Governor (the rule that picks the speed) and Temperature (estimated, from a sensor the app thinks belongs to the CPU). Under the tabs, the Units row has a °F / °C menu that picks the unit; the Battery tab uses the same choice.
  • System Statistics: Processes and Threads (only with a working mode) and Uptime (time since the phone started).
  • Cluster boxes: cores are grouped by speed range (fast cores and slow, thrifty ones). Each group shows Min, Current and Max frequency in MHz or GHz. A high Current close to Max means the group is working hard; it drops when idle.

RAM

RAM is the working memory. The big number is the share in use; the line under it reads for example Using 4.1 GB of 7.5 GB. The boxes show:

  • Used: total minus Available.
  • Available: what apps could get right now, counting cache that Android can give back. This is the number to watch.
  • Swap used and Swap total: extra memory made from storage or by compression.
  • Under Memory Information: Free (memory doing nothing), Buffers and Cached (kept to speed things up), Swap free, Swap cached and Page size.
Tip. Android keeps memory busy on purpose. A high Used and a small Free are normal. Worry only when Available gets very low and the phone is slow.

GPU

The GPU draws the picture on your screen. The big number is its load. Phones do not all expose it, so you may see Not available on this phone. Some show ~40% (by clock speed), a rough guess from the chip's speed. Under it, GPU Information says whether Vulkan is supported (and its API version) and the OpenGL ES version (Vulkan and OpenGL ES are the two ways apps draw graphics on the chip).

The GPU renderer card is at the very top of the tab, above the graph, and shows in large letters which renderer is in use (Default, OpenGL or Vulkan). Its drop-down (working mode needed) offers OpenGL, and Vulkan if the phone supports it (plus Default until you pick one). Choosing one sets the system's drawing engine and restarts System UI (the status and navigation bars) to apply it, with a visible flicker. To go back, choose the other one, or restart the phone (a setting made this way normally does not survive a restart).

Careful. Change the renderer only if you know why, for example to test an app. Some apps and games behave differently or look wrong with the other engine.

Battery

The big number is the charge. Under it: the state (Charging, Discharging, Not charging, Full) and the source (AC, USB, Wireless). The boxes: Temperature, Current, Voltage and Health (Good, Overheat, Dead, Over voltage, Failure, Cold, or Unknown). Some phones show current as negative while the battery is in use, others as positive. Battery Information adds Technology, Source, Power in watts, Charge in mAh, Capacity (estimated), Time left (estimated) (only while discharging) and Charge cycles (N/A unless Android 14 or later reports it). The estimates are rough.

Network

The big number is the speed now, down and up added together; the line under it shows each: down 1.2 MB/s up 80 KB/s (with arrows on screen). Below are the active connections, busiest first, for example wlan0 (Wi-Fi) or rmnet (mobile data), then Network Statistics: Total received and Total sent since the phone started.

Why the numbers differ from other apps

  • Each app measures at its own moments and over its own span, so figures never match exactly.
  • The per-app CPU percentage comes from the phone's own ps command (the command that lists running programs), which may be an average over the whole time the process has run, so it can look low or high compared with what happens this second.
  • RAM here counts what Android says is Available. Apps that report only Free show smaller numbers.
  • Temperature is estimated from a sensor, and GPU load is not available on every phone.
