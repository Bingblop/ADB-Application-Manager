# Extra Settings — design brief (owner: "they look like crap, redesign them for the webview; things that look good and sell users on installing")

The Kotlin-app screenshots are only a list of WHAT to include. Do not copy their look (cramped cards, ALL-CAPS titles that collide with badges, badges that wrap letter by letter, flat grey text walls, a "sensor simulation" card). Design for the WebView with the app's own language and make it feel like a premium, trustworthy system tool.

## Ground rules
- Use ONLY the app's theme tokens so every palette/light/dark combination works: --bg-base, --bg-surface, --bg-card, --bg-card-hover, --border-glass, --accent, --accent-glow, --secondary, --text-main, --text-muted, --text-dim, --on-gradient (text on the accent→secondary gradient). Green/amber/red status colours must also be derived so they read in light and dark (define --ok/--warn/--bad locally in the Extra Settings root if the app has none, with light and dark values).
- Works at 360 px, 412 px and tablet widths. No horizontal scroll, no text clipped, no badge ever wraps (white-space:nowrap; the title shrinks with ellipsis instead). Touch targets >= 44 px. Numbers use font-variant-numeric: tabular-nums.
- Motion: subtle (ring fill, count-up, press scale, chevrons). Honour prefers-reduced-motion and the app's "Expressive Animations" setting (html.expressive-anim). Never animate layout in a way that shifts content while the user taps.
- Language: sentence case titles (not ALL CAPS paragraphs). Every section has: a gradient icon tile, a title, one plain sentence saying what it does and why you would use it, and one status pill at the right (single line). A small "What does this do?" expander holds the detail. Strings go through the app's i18n and all 13 dictionaries.
- Trust cues (these are what sell the tab): a calm line in each risky section — "Nothing runs until you confirm", "The card reads the phone back and shows what it really holds", and in Read-Only mode a visible lock state ("Read-only: viewing only") with the controls disabled and explained, never hidden.
- The page header of the tab: title "Extra Settings", subtitle "Tweaks and controls that Android hides", and a row of 3-4 live summary chips (e.g. Private DNS: AdGuard · Animations: 1× · RAM 53% · Battery 49%) that scroll the page to that section when tapped.

## Sections (in this order) and their look
1. DNS (owned by the DNS agent — match this language): provider tiles as a 2-column grid with logo-less coloured monogram, name, host, a live ping value that fills in as the speed scan runs; fastest one gets a "Fastest" pill; "Test speeds" is the primary button with a progress sweep.
2. Animation speed: three rows (Window animations, Transition animations, Animator duration). Each: label + plain meaning, a slider 0–10 (step 0.05, log-ish feel not required) tied to a number input that accepts ANY number (typing beyond the slider range is allowed and shown with a warning pill above 10), quick chips (Off · 0.5× · 1× · 1.5× · 2×), and a live preview dot that moves back and forth at the chosen speed so the user SEES the effect. One "Apply" and one "Reset to 1×" at the bottom; the card reads the real values back after applying.
2b. Adaptive brightness bias (owner request): "Make auto-brightness darker or lighter". Edits the system-table setting `screen_auto_brightness_adj` (float, range -1.0 to 1.0; 0 = neutral, above 0 brighter, below 0 darker). Write with `settings put system screen_auto_brightness_adj <value>` through the working mode; read with `settings get system screen_auto_brightness_adj`. UI: a slider -1…+1 (step 0.05) whose track shades from dark through neutral to bright, with a number field that accepts typed values and REJECTS anything outside -1…1 with a plain message (clamp is not silent), quick chips (Darker -0.5 · Neutral 0 · Brighter +0.5), the current value shown big ("+0.30 brighter than normal"). Also read `settings get system screen_brightness_mode` (1 = adaptive on): if adaptive brightness is OFF show a clear notice "Adaptive brightness is off, so this has no effect until you turn it on in Display settings" with a button that opens Android's display settings (do NOT switch adaptive brightness on silently). Read the value back after applying and show what the phone holds; Samsung One UI may reset or ignore it — say so honestly if the read-back differs. Reset button writes 0. Live preview is not possible (the phone's own brightness changes), so show a small before/after hint instead. Read-Only/no mode: disabled with explanation.
3. Device telemetry & specs: three ring gauges in one row (RAM, Storage /data, Battery) — conic/SVG rings filled in the accent→secondary gradient with the big percentage in the middle, label and "8.5 of 15.8 GB" underneath; battery ring turns amber/red when low and shows charging bolt; under the rings a 2-column grid of spec chips (Model, Android/One UI, Kernel, Uptime, Battery temp + health, Swap used) with icons; refresh icon button (spins while loading) and a Copy button that copies a clean text report. Skeleton shimmer while loading; if a value cannot be read show "Not available" muted, never blank or NaN.
4. Power & reboot: a 2-column grid of tiles (Reboot, Soft reboot, Recovery, Power off, Bootloader, Restart SystemUI) — each with a coloured icon tile, bold title and a one-line subtitle ("Restarts the phone", "Restarts Android only, apps close"). Power off and Bootloader get a red/amber tint. A tap opens a bottom sheet (use the app's existing sheet component) explaining exactly what will happen and a clear confirm button; Power off and Bootloader use press-and-hold to confirm. Disabled with an explanation in Read-Only or when no working mode.
5. Doze & power governor: a horizontal phase timeline (Active → Light idle → Deep idle → Maintenance) with the current phase highlighted from `dumpsys deviceidle`; action buttons below (Force deep doze, Step to next phase, Wake device) and a motion-sensor switch with a one-sentence explanation. Power profiles as three selectable cards (Performance · Balanced · Ultra saver), each with icon, name and one line of what it changes; the selected one has the gradient border; applying one shows the read-back.
6. Zram & memory: a big compression badge ("3.0× compression" single line) next to a stacked bar showing Compressed in RAM / Saved / Free swap; a 2x2 stat grid (Allocated, Compressed in RAM, Uncompressed data, RAM saved — RAM saved in the ok colour); two buttons: Reclaim disk caches (primary) and Drop page caches (secondary, says it needs root and when it will do nothing).

## Quality bar (check it yourself with real screenshots)
- Use Chromium via Playwright (PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers; do not run playwright install) to take screenshots of the whole tab at 360 and 412 px wide in dark and light and in at least two palettes (default cyan/violet and one warm palette) and LOOK at them (Read the PNG files). Fix anything cramped, clipped, low-contrast or misaligned before pushing. Save the screenshots in the scratchpad and mention their paths in your report.
- Add UI tests that assert: no horizontal overflow at 360 px, no badge/pill wraps (offsetHeight equals one line), controls disabled in Read-Only with an explanation visible, long values and long translations don't break the layout (use the app's pseudo-locale / a long-string run).
